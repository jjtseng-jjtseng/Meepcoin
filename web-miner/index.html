    • One predetermined nonce from a committed, daemon-generated local-devnet vector. Nothing is searched for.
    • Hashed once by this browser’s WebAssembly build, once by the server’s own WebAssembly build, and once by the local native helper. All three are built from the same implementation lineage (the same C++ source), so their agreement catches a build, toolchain, marshalling or context fault — not a mistake shared by all of them.
    • Live local native helper — a local native C++ child process, given the exact same recorded context. It starts only after you press Start and is stopped with the local server.
    • Mock daemon — an in-memory object with counters. No socket, no RPC, no chain.
    • No daemon and no blockchain is contacted.
    • No block is mined, submitted or accepted, and nothing is created.

    REAL LOCAL DAEMON — PRIVATE, ON THIS COMPUTER

      • MeepCoin daemons built from this repository run privately on this computer in their test network mode; the labels above say exactly how (one offline node, or two nodes paired only with each other). Their test coins have no value.
      • An accepted block pays its coinbase to an address fixed by whoever started this local server, before this page loaded. This page does not choose it, is never told it, and cannot change it — nothing you send from here can move a reward. Those coins exist only on the private chain on this computer.
      • This browser searches each fresh block template it actually starts at most once: at most 8,192 nonces or 120 seconds per template, whichever comes first. Trusted local server code may supersede queued work before the browser starts it; that skipped template is never searched. How many positions one Start covers — one, or a finite development sequence of at most 32 — is stated by the labels above, before you press Start. No answer is known in advance, and finding none is a normal outcome.
      • A nonce that meets the daemon’s target is recomputed by the server’s WebAssembly build, the local native helper and the daemon, and submitted to that private daemon at most once per template, never retried. Success means the daemon’s own canonical readback shows that exact block on top of its chain — nothing more.

      Connecting to the local development pool… what this page will do depends on which mode that server is running, so nothing is claimed until it says.

      This page runs the frozen MeepHash-W v2 proof-of-work in your browser against a development pool server on this machine only. It is an engineering demo of the mining loop. There is no public MeepCoin network and no coin of value; in its real-daemon mode the local server may run a private development network on this computer only.

      Before you press Start — what this will do

      What you are mining
      A local synthetic development job — no coins or rewards. Shares that this page finds are counted by a server on your own computer and then discarded. Nothing is earned, credited, stored or paid out.
      Destination
      None. No wallet, no address, no payout and no account are involved, and the page will never ask you for one. Results go to the local server that served this page and nowhere else.
      Algorithm
      Frozen MeepHash-W v2, compiled to WebAssembly (meepow/wasm/meepow.wasm), run on your CPU.
      How a share is checked
      The pool never trusts a hash this page sends — it recomputes the nonce itself, on two independently built copies of frozen v2: its own WebAssembly build and a native build compiled with a different toolchain. A share counts only if those two produce byte-for-byte identical results and the agreed hash meets the target. If the two ever disagree, this pool stops verifying for good, stops your mining, and accepts nothing further until it is restarted. What this is not: both builds compile the same C++ source, so this catches a compiler, toolchain or runtime difference — it cannot catch a mistake that is in the algorithm itself.
      CPU use
      Exactly 1 Web Worker on 1 CPU thread. The page never mines on the main thread and never starts a second worker.
      Memory — in this browser
      Roughly 46.3 MiB in that worker, allocated only after you press Start — a 32 MiB dataset plus an 8 MiB scratchpad plus module overhead. That figure is the value measured in Chrome and Firefox in docs/BROWSER_V2.md; treat it as an estimate for your browser, not a guaranteed ceiling. Stop frees it by terminating the worker.
      Memory — in the local pool
      The development pool on this machine is a separate process, and pressing Start makes it load two copies of the algorithm so it can check your work against both. Reported separately below, because they are different measurements of different things:
      • Its own WebAssembly build — roughly 46.3 MiB of Wasm heap, the same figure as the browser worker, measured the same way.
      • A native build, in its own child process — exactly 40 MiB of algorithm memory (a 32 MiB dataset plus an 8 MiB scratchpad). That is what the algorithm allocates, not the child process's resident memory: the real process is larger, and this page does not measure it.
      Please do not read those as one total. They are two numbers with different meanings, and neither of them is the pool's actual RSS, which nothing here measures. Being honest about the rest: Stop terminates the browser worker immediately, but it does not free the pool's memory or its native child — those are released when you stop the pool itself (Ctrl-C in its terminal). Until you press Start the pool has not loaded, compiled or started either build and has allocated none of this.
      Heat and battery
      Mining keeps one CPU core busy. Expect the fan to spin up, the device to get warm and a laptop on battery to discharge noticeably faster. Press Stop, or just leave this tab, and it ends. For a real-template search, you can choose a pause between batches before pressing Start. That lowers the hash rate, but does not guarantee a particular CPU percentage or reduce the memory used by the browser and local pool.
      Work batch size
      The worker pauses to check for a Stop message every 4 hashes. This value comes from the server job.

      Nothing on this page starts by itself. Until you press Start, this browser has not requested the algorithm at all, and the local pool has not loaded, compiled or started either of its two builds, has not allocated their memory, has not launched the native child process, and has not computed a single hash. (For completeness: at startup the pool does read about 58 KiB of the algorithm build files and check their fingerprints, so it can later serve you exactly the bytes it checked. Reading and fingerprinting two small files is not mining.) Pressing Start asks the pool to load its verifier first; only when it answers does this page create its one worker. Hiding this tab stops mining, and making it visible again does not resume — you have to press Start again.

      One run ends after one accepted share. Every job here carries the same fixed synthetic context, target and nonce window, so the demonstration stops on purpose rather than re-issuing work that would look fresh but is not. Press Start again for another run.

      Controls

      A quieter search may find fewer hashes before the same time limit. Choose before Start; Stop or hiding this tab still ends the session.
